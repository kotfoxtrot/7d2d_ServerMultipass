# Server Multipass

Один мод со всем, что обычно нужно публичному серверу 7 Days to Die: дома, телепорт к игроку,
напоминания о кровавой луне, перезагрузка по расписанию, сортировка сундуков, защита клаймов,
рюкзаков и локаций заданий, выдача предметов, теги в чате, приветствие новичков, замки на только
что поставленных ящиках, дверях и транспорте и аренда торговых автоматов. Каждая функция — отдельный модуль, который включается
и выключается в одном файле.

> Серверный мод · выделенный сервер 7 Days to Die 3.2 · игрокам ничего ставить не нужно

[English version](README.md)

## Что умеет

| модуль | что даёт | включён после установки |
|---|---|---|
| [Home](#home) | `/home`, `/sethome`, `/delhome`: личные точки телепорта в своём клайме | да |
| [Tpa](#tpa) | `/tp <игрок>`, `/tpa`, `/tpd`: телепорт к другому игроку с его согласия | да |
| [BloodMoon](#bloodmoon) | `/bm` и ежедневное напоминание, сколько дней до кровавой луны | да |
| [Welcome](#welcome) | приветствует новичка в чате и встречает вернувшегося игрока | да |
| [ChestSort](#chestsort) | ящик с надписью `sort` раскладывает предметы по ящикам базы | да |
| [Give](#give) | консольная команда `mp-give`: предметы сразу в инвентарь игрока | да |
| [Shutdown](#shutdown) | перезагрузка по расписанию с отсчётом в чате | нет |
| [ClaimGuard](#claimguard) | в клайме ящики и верстаки открывают только владелец и его друзья | нет |
| [ClaimLimit](#claimlimit) | клайм сверх лимита возвращается игроку, а не отключает самый старый | да |
| [BackpackGuard](#backpackguard) | рюкзак после смерти 30 минут принадлежит только хозяину | нет |
| [PoiGuard](#poiguard) | в локацию нельзя зайти, пока там выполняет задание другой игрок | нет |
| [ChatDecor](#chatdecor) | тег и цвета в чате для выбранных игроков, например VIP | нет |
| [Autolock](#autolock) | поставленные игроком ящики, двери и транспорт сразу заперты на него | нет |
| [VendingRental](#vendingrental) | аренда торговых автоматов: договор, продление из кассы, лимит на игрока | нет |

- Модули включаются и выключаются в `ServerMultipass.xml`. Изменение применяется через несколько
  секунд после сохранения файла, перезапуск не нужен. Исключение — модули, меняющие XML игры: они
  включаются и выключаются после перезапуска сервера, см. [Модули с XML игры](#модули-с-xml-игры).
- Мод поставляется с готовыми файлами настроек и текстов для каждого модуля, над каждой строкой —
  пояснение. Сам мод эти файлы не создаёт: модуль, у которого нет своего файла, не включается.
- Все сообщения игрокам — на английском и русском. Игрок выбирает язык командой `/lang`, а новичок
  сразу получает язык своей страны. Любой текст можно поменять, можно добавить свой язык.
- Если модуль сломался, он сам выключается и пишет причину в лог. Остальные продолжают работать.
- Игрокам ничего устанавливать не нужно.

## Установка

### Из архива

1. Распакуйте архив в `<сервер>/Mods/` так, чтобы получилась папка
   `<сервер>/Mods/1_ServerMultipass/` с файлами `ServerMultipass.dll`, `ModInfo.xml`,
   `ServerMultipass.xml` и папками `Settings`, `Lang` и `Xml`.
2. По желанию скачайте `GeoLite2-Country.mmdb` с [github.com/P3TERX/GeoLite.mmdb](https://github.com/P3TERX/GeoLite.mmdb) и положите его в
   `<сервер>/Mods/1_ServerMultipass/Data/` (если папки ещё нет, создайте её).
3. Просмотрите `ServerMultipass.xml` и файлы в `Settings`, см. [Настройка](#настройка), затем
   перезапустите сервер.

### Из исходников

```bash
dotnet build -c Release -p:GameRoot=/путь/к/серверу
```

`GameRoot` — корень выделенного сервера, папка, в которой лежат `7DaysToDieServer_Data/Managed` и
`Mods/0_TFP_Harmony`. Без `-p:GameRoot` берётся путь, прописанный в `.csproj`.

Сборка кладёт готовую папку мода — DLL, `ServerMultipass.xml`, `Settings`, `Lang` и `Xml` — в
`bin/1_ServerMultipass/`; `-p:PackageDir=/другая/папка` кладёт её в другое место. С
`-p:Deploy=true` мод ставится в `<GameRoot>/Mods/1_ServerMultipass/`: DLL, `ModInfo.xml`, README и
папка `Xml` заменяются, ваши `ServerMultipass.xml`, `Settings` и `Lang` остаются как есть,
добавляются только недостающие файлы.

### Обновление

Замените `ServerMultipass.dll`, `ModInfo.xml` и папку `Xml` целиком, оставьте свои
`ServerMultipass.xml`, `Settings` и `Lang` и перезапустите сервер. Сам мод в эти файлы не пишет, кроме `mp enable` и `mp disable`,
которые переключают модуль в `ServerMultipass.xml`.

Если в новой версии появилась настройка, модуль или текст, лог напишет, чего не хватает в ваших
файлах, и такой модуль не включится, пока вы это не добавите: скопируйте строку из файлов новой
версии.

### Имя папки

Папка должна начинаться с `1_`. Моды загружаются по алфавиту: первым должен идти `0_TFP_Harmony`, а
Server Multipass должен видеть сообщения чата раньше других модов, чтобы его команды не попадали в
общий чат.

## Настройка

Всё, что настраивается, поставляется вместе с модом в готовом виде. Мод никогда не создаёт и не
восстанавливает эти файлы: что лежит в папке, с тем он и работает.

```
Mods/1_ServerMultipass/
├── ModInfo.xml
├── ServerMultipass.dll
├── ServerMultipass.xml      в поставке: включение модулей и общие настройки
├── Settings/<Модуль>.xml    в поставке: настройки каждого модуля
├── Lang/<Модуль>.csv        в поставке: все тексты, которые видят игроки
├── Xml/<Модуль>/            в поставке: XML игры модуля, см. «Модули с XML игры»
└── Data/
    ├── Players.json         пишет мод: языки, выбранные игроками через /lang
    └── GeoLite2-City.mmdb   база GeoIP, по желанию, кладётся вручную
```

Данные, относящиеся к миру, например дома игроков, хранятся рядом с сохранением:
`Saves/<Мир>/<Игра>/ServerMultipass/`. При вайпе они удаляются вместе с миром и попадают в бэкапы
вместе с сейвом.

Модуль запускается, только когда его файлы на месте и в порядке: `Settings/<Модуль>.xml` для модуля
с настройками и `Lang/<Модуль>.csv` для модуля с текстами. В файле должна быть каждая настройка с
правильным значением. Если что-то отсутствует или неверно, модуль не включается, а в логе точно
написано, что именно, например `Settings/Home.xml: property Cooldown is missing`. Встроенных
значений в моде нет, и сам он ничего не дописывает: всё берётся из этих файлов. Если файл удалён или
испорчен, возьмите его из архива своей версии.

Каждый файл перечитывается через несколько секунд после сохранения. Если в новой версии файла
ошибка, она не применяется: в логе будет написано, что не так, а в работе останутся прежние значения.
Все строки лога мода начинаются с `[Multipass]`.

### Модули с XML игры

Некоторые модули меняют XML игры: блоки, предметы, трейдеров, окна. Их XML лежит в
`Xml/<Модуль>/`, и сервер подключает его при запуске:

- файлы в `Xml/<Модуль>/` применяются, только если модуль включён в `ServerMultipass.xml` в момент
  запуска сервера;
- файлы в `Xml/<Модуль>/Always/` применяются всегда, даже когда модуль выключен. Там то, без чего
  не загрузится сохранение мира, например предметы и трейдеры, которые уже есть в мире, и
  `Localization.csv` модуля;
- `${Настройка}` в этих файлах заменяется значением из `Settings/<Модуль>.xml`, например
  `${RentPrice}`.

Такой модуль включается и выключается только после перезапуска сервера: игроки получают XML игры
при входе, и на ходу его не поменять. `mp enable` и `mp disable` сохраняют выбор, а `mp`, пока
перезапуска не было, показывает `on (off after restart)` или `off (on after restart)`. Настройка,
которая подставляется в XML, тоже применяется после перезапуска, лог об этом предупреждает.
Остальные настройки и тексты таких модулей применяются на ходу, как у всех.

Папка `Xml` — часть мода, как DLL: при обновлении она заменяется целиком. Значения меняйте в
`Settings`, а не в XML. Что в итоге получила игра, видно в `Saves/<Мир>/<Игра>/ConfigsDump/`.

### ServerMultipass.xml

```xml
<ServerMultipass>
  <property name="ChatPrefix" value="/" />
  <property name="DefaultLanguage" value="english" />
  <property name="GeoIp" value="true" />
  <property name="GeoIpDatabase" value="" />
  <property name="CountryLanguages" value="RU:russian,BY:russian,KZ:russian" />
  <modules>
    <module name="Home" enabled="true" />
    <module name="Shutdown" enabled="false" />
    ...
  </modules>
</ServerMultipass>
```

| настройка | в поставке | что значит |
|---|---|---|
| `ChatPrefix` | `/` | символ, с которого начинается команда в чате. Если меняете, поправьте и подсказки в файлах `Lang` |
| `DefaultLanguage` | `english` | язык для игроков, которые не выбрали свой и не определились по стране |
| `GeoIp` | `true` | выбирать язык новичка по его стране |
| `GeoIpDatabase` | пусто | имя файла GeoIP в папке `Data` мода. Пусто — берётся первый найденный там файл `.mmdb` |
| `CountryLanguages` | `RU:russian,BY:russian,KZ:russian` | какой язык получают игроки из какой страны |

После того как положили или заменили базу GeoIP, выполните `mp reload` или перезапустите сервер.

`enabled="true"` включает модуль, `enabled="false"` выключает. Консольные команды
`mp enable <модуль>` и `mp disable <модуль>` делают то же самое и сохраняют изменение в этот файл.

### Кому доступны команды чата

Команды чата доступны всем. Чтобы ограничить команду, добавьте строку в раздел `<commands>` файла
`serveradmin.xml`, с `mp.` перед именем команды:

```xml
<permission cmd="mp.home" permission_level="100" />
```

Теперь `/home` доступна только игрокам с уровнем прав 100 и ниже (0 — владелец сервера).

### Тексты и языки

`Lang/<Модуль>.csv` — это таблица: в первой колонке ключ, дальше по колонке на каждый язык. Её можно
открыть любым текстовым редактором или в таблицах (UTF-8, разделитель — запятая). Цвета задаются
игровыми кодами `[RRGGBB]текст[-]`, вместо `{0}`, `{1}` мод подставляет значения. Строка `Tag` — это
цветная приставка ко всем сообщениям модуля.

Чтобы добавить язык, добавьте колонку с его названием (`german`, `french`, ...) и заполните тексты.
Если текста на каком-то языке нет, он берётся из `DefaultLanguage`, а затем из первой колонки, где
он есть.

Игроки управляют языком так:

- `/lang` — показать текущий язык и доступные
- `/lang ru` или `/lang russian` — выбрать язык
- `/lang auto` — вернуть автоматический выбор

## Home

Игроки сохраняют именованные точки и возвращаются к ним с перезарядкой.

- `/sethome <имя>` сохраняет текущее место; то же имя ещё раз переносит точку
- `/home` показывает список домов, `/home <имя>` переносит туда
- `/delhome <имя>` удаляет дом

С `OnlyInClaim` дом можно сохранить только внутри своего клайма, клайм друга не подходит. Правило
действует и на админов. С `RemoveWithClaim` дом, стоящий в клайме владельца, удаляется, как только
его не накрывает ни один клайм владельца: блок клайма разрушили, подобрали или его отключил лимит
клаймов. Владелец сразу получает в чат `Ваш клайм разрушен, дом удалён: base`, а если был не в игре —
при следующем входе; каждое такое удаление записывается в лог. Дома, сохранённые вне клайма,
например до включения `OnlyInClaim`, остаются, пока их не накроет клайм владельца.

В транспорте телепорт не работает. Дома относятся к миру и удаляются вместе с ним при вайпе.

| настройка | в поставке | что значит |
|---|---|---|
| `Limit` | `3` | сколько домов может сохранить один игрок |
| `Cooldown` | `900` | секунд между двумя телепортами домой, 0 — без ожидания |
| `OnlyInClaim` | `true` | `/sethome` работает только внутри своего клайма |
| `RemoveWithClaim` | `true` | дом удаляется вместе с клаймом, в котором стоит |

## Tpa

Игрок просит телепорт к другому игроку, тот принимает или отказывает.

- `/tp <ник>` отправляет запрос, можно написать часть ника
- `/tpa` принимает запрос, `/tpd` отклоняет

| настройка | в поставке | что значит |
|---|---|---|
| `RequestTimeout` | `60` | сколько секунд запрос ждёт ответа |
| `Cooldown` | `1800` | секунд между двумя телепортами одного игрока, 0 — без ожидания |

## BloodMoon

`/bm` показывает, сколько дней осталось до кровавой луны. Каждый игровой день в `NotifyHour` все, кто
в игре, получают напоминание, а в день кровавой луны — предупреждение, что они придут этой ночью.

| настройка | в поставке | что значит |
|---|---|---|
| `NotifyHour` | `18` | игровой час ежедневного напоминания |
| `NotifyEveryDays` | `1` | напоминать, когда оставшиеся дни делятся на это число: 1 — каждый день, 7 — раз в неделю, 0 — только в день луны |

## Welcome

Когда игрок впервые заходит на сервер, все, кто в игре, видят приветствие. При каждом следующем входе
игрок получает личное сообщение «с возвращением». Тексты — в `Lang/Welcome.csv`.

| настройка | в поставке | что значит |
|---|---|---|
| `GreetNewPlayers` | `true` | приветствовать новичка в чате для всех, кто в игре |
| `GreetReturningPlayers` | `true` | писать вернувшемуся игроку «с возвращением» в личку |

## ChestSort

Поставьте на базе ящик с табличкой для надписи, напишите на ней `sort`, сложите в него предметы и
закройте. Каждый предмет, который уже лежит в другом ящике этой же базы, переедет туда: сначала в
неполные стопки, потом в свободные ячейки того ящика. Предметы, которых нет ни в одном ящике,
останутся в сортировочном.

База — это ваш клайм вместе с вашими клаймами рядом. Ящики, которые сейчас кто-то открыл, и ячейки,
закреплённые игроком, не трогаются.

| настройка | в поставке | что значит |
|---|---|---|
| `ChestName` | `sort` | надпись на сортировочном ящике |
| `MergeDistance` | `5` | ваши клаймы ближе, чем размер клайма плюс столько блоков, считаются одной базой |

## Give

Консольная команда для админов и магазинных панелей: предмет сразу попадает в инвентарь игрока, а
игрок получает сообщение об этом. Каждая выдача записывается в лог.

```
mp-give <игрок|all> <предмет> [количество] [качество] [прочность]
```

- `игрок`: ник, entity id, EOS или Steam id; `all` — всем, кто в игре
- `количество`: по умолчанию 1; `качество`: от 1 до 6, по умолчанию 1; `прочность`: в процентах, по умолчанию 100

Примеры: `mp-give Alice drinkJarBoiledWater 5`, `mp-give all gunHandgunT1Pistol 1 6`.

| настройка | в поставке | что значит |
|---|---|---|
| `Aliases` | пусто | другие имена той же команды, например `st-GiveItem,gi` для магазинной панели. Применяется после перезапуска сервера |
| `MaxCount` | `1000000` | сколько предметов можно выдать одной командой |

Если у вас ещё стоит отдельный GiveItemMod с теми же именами команд, сначала уберите его.

## Shutdown

Останавливает сервер по расписанию, чтобы хостинг запустил его заново. Перед этим все, кто в игре,
получают предупреждения в чате, в последнюю минуту — предупреждение, что прогресс может не
сохраниться, затем всех кикает с сообщением и сервер останавливается. Во время кровавой луны отсчёт
ждёт.

**Мод только останавливает сервер.** Запустить его заново должно что-то другое: монитор LinuxGSM,
служба systemd с `Restart=always` или панель хостинга.

- `/rc` в чате показывает, сколько осталось
- `mp-shutdown` в консоли показывает ближайшую перезагрузку, `mp-shutdown 10` переносит её на 10
  минут от текущего момента, `mp-shutdown 03:00` — на 3 часа ночи, `mp-shutdown off` отменяет до
  следующего запуска

| настройка | в поставке | что значит |
|---|---|---|
| `Schedule` | `240` | минуты после старта сервера (`240`), время суток (`03:00`) или несколько времён (`03:00,15:00`), по местному времени сервера |
| `AlertMinutes` | `15,10,5,4,3,2,1` | за сколько минут до перезагрузки всех предупреждать |
| `AlertOnLogin` | `false` | сообщать каждому вошедшему, сколько осталось |
| `JoinAlertMinutes` | `5` | всё равно сообщить вошедшему, если перезагрузка уже так близко |
| `FinalWarningMinutes` | `1` | с этой минуты предупреждать, что прогресс может не сохраниться |
| `KickLeadSeconds` | `5` | за сколько секунд до перезагрузки кикать всех игроков |
| `ShutdownGraceSeconds` | `3` | минимальная пауза между киком и остановкой |
| `ShutdownTimeoutSeconds` | `15` | сколько максимум ждать, пока игроки отключатся |
| `FreezeDuringBloodMoon` | `true` | ставить отсчёт на паузу во время кровавой луны |
| `ChatCommands` | `rc` | команды чата, показывающие оставшееся время |

## ClaimGuard

В клайме ящики, верстаки, генераторы и мешки с лутом открывают только владелец и его друзья. Мешки с лутом открывает и группа владельца, чтобы после
кровавой луны на чужой базе лут можно было поделить; владелец при этом должен быть в игре. Чужой
слышит звук отказа и получает сообщение. Торговые автоматы остаются открытыми для торговли, админов
защита не касается, а рюкзаки погибших — забота [BackpackGuard](#backpackguard). клайм, владелец
которого слишком долго не заходил, перестаёт защищать, как и в самой игре. Настроек нет.

## ClaimLimit

В самой игре, если игрок ставит клайм сверх `LandClaimCount` из `serverconfig.xml`, его самый старый
клайм молча отключается и перестаёт защищать, и многие этого даже не замечают. С этим модулем такой
клайм просто не ставится: блок возвращается в инвентарь, игрок слышит звук отказа и получает
`Достигнут лимит 3/3 клаймов!`. При каждой удачной установке видно, сколько клаймов из лимита
занято: `Установлен 2/3 блоков клайма!`.

Лимит — `LandClaimCount` из `serverconfig.xml`; `setgamepref LandClaimCount` применяется за
секунду. Игра у игрока сама применяет лимит в момент установки блока, ещё до того, как об этом узнает
сервер, поэтому, пока модуль включён, внутренний лимит игры держится на единицу выше
`LandClaimCount`: ни сервер, ни игра у игрока старый клайм не отключают, а лишний не пускает модуль.
При выключении модуля внутренний лимит игры возвращается к `LandClaimCount`. Менять его через
`setgamestat LandClaimCount` не нужно: модуль вернёт своё значение за секунду.

Если снизить `LandClaimCount` ниже, чем у кого-то уже есть, старые клаймы останутся, но новые игрок
не поставит, пока не окажется в пределах лимита. Правило действует и на админов, как и игровой
лимит. Каждый отказ записывается в лог. Настроек нет.

## BackpackGuard

Когда игрок погибает, выпавший рюкзак какое-то время может открыть только он сам. Остальным пишет, чей
это рюкзак и сколько ещё длится защита. Админов защита не касается.

| настройка | в поставке | что значит |
|---|---|---|
| `ProtectionMinutes` | `30` | сколько реальных минут после смерти рюкзак защищён |
| `ExemptFriends` | `true` | друзья владельца тоже могут открыть рюкзак |

## PoiGuard

Пока игрок выполняет задание в локации, других игроков, которые туда заходят, телепортирует обратно
наружу — туда, где они стояли до входа. Защита действует, пока идёт задание, и во время сбора лута
после него (около двух игровых часов, это правило самой игры). Владельца задания, его группу, друзей
и админов никогда не выносит. Каждое такое перемещение записывается в лог.

клайм, зона которого задевает локацию, и спальник внутри локации сразу убираются и возвращаются
игроку.

| настройка | в поставке | что значит |
|---|---|---|
| `EvictStrangers` | `true` | выносить чужих игроков из локации задания |
| `BlockClaims` | `true` | запрещать клаймы, задевающие локацию |
| `BlockBedrolls` | `true` | запрещать спальники внутри локаций |

## ChatDecor

Даёт выбранным игрокам тег и цвета в чате. Игроки перечисляются в `Settings/ChatDecor.xml`, по
строке на игрока:

```xml
<player id="EOS_..." tag="[00CC00]VIP[-]" nameColor="FFD700" messageColor="FFFFFF" />
```

`id` — EOS или Steam id игрока, его показывает консольная команда `lp`. Цвета — в формате `RRGGBB`.

С `TagBeforeName="false"`, как в поставке, тег стоит сразу после ника: `Ник: [VIP] сообщение`.
Так продолжает работать игровой чёрный список: кто заблокировал этого игрока, по-прежнему не видит
его сообщений. С `TagBeforeName="true"` получится классический вид `[VIP] Ник: сообщение` с цветным
ником, но тогда чёрный список перестаёт скрывать эти сообщения.

| настройка | в поставке | что значит |
|---|---|---|
| `TagBeforeName` | `false` | классический вид: тег и цветной ник впереди, см. выше |

## Autolock

Ящик, дверь или транспорт, которые поставил игрок, сразу заперты на него. В самой игре они
ставятся незапертыми, и открыть их может любой, пока владелец не запрёт их вручную.

- Запирается только то, что поставил игрок. Локации, лут и всё, что уже стоит в мире, не меняются.
- Что владелец отпер, остаётся незапертым и после перезапуска, а улучшенный блок сохраняет свой
  замок как был.
- Владелец отпирает, запирает и ставит код как обычно. Никто другой, включая друзей, не откроет
  запертый ящик, дверь или транспорт без кода: так в игре работает любой замок. Чтобы друг поехал
  пассажиром, отоприте транспорт или сообщите ему код.
- Бандиты открывают только незапертые двери, так что запертая дверь не пустит и их.

Запираются деревянный, железный и стальной ящики (Storage Crate) и все двери, люки, ворота, ставни
и разводные мосты, которые в игре можно запереть. У сейфов, оружейных сейфов, шкафчиков и дверей на
электричестве замка в игре нет, их модуль не трогает. Замок — обычный игровой, ровно такой же, как
если бы владелец запер вручную.

| настройка | в поставке | что значит |
|---|---|---|
| `LockStorage` | `true` | запирать ящики |
| `LockDoors` | `true` | запирать двери, люки, ворота, ставни и разводные мосты |
| `LockVehicles` | `true` | запирать транспорт |

Отдельные моды LockStorageOnPlace и LockVehicleOnPlace с этим модулем не нужны.

## VendingRental

Аренда торговых автоматов на обычных игровых автоматах. Для торговли необходимо платить дань Дюку
всего Невезгана:

- автомат у трейдера (`cntVendingMachineTrader`), пока свободен, продаёт «Договор аренды». Покупка
  договора оформляет автомат на игрока на `RentDays` дней;
- автомат, который игрок поставил сам (`cntVendingMachine`), может арендовать только тот, кто его
  поставил. Пустой автомат можно забрать и поставить в другом месте: аренда и касса переезжают
  вместе с ним. Автоматы, поставленные до включения модуля, остаются обычными.

Аренда продлевается сама: за день до конца из кассы автомата списывается `RentPrice`. Если в кассе
не хватает, аренда кончается, товары и касса сгорают. Игровая кнопка «Арендовать» скрыта, срок
аренды показывает сам автомат.

Игрок получает в чате три сообщения: сколько автоматов он арендовал при покупке договора
(`Арендовано автоматов: 2/3`), что лимит `MaxRentalsPerPlayer` исчерпан (деньги за договор
возвращаются) и, за день до конца аренды, сколько дюков доложить в кассу для продления.

Каждая покупка в арендованном автомате проверяется на сервере: сама игра верит тому, что прислал
игрок. По желанию автомат время от времени продаёт товар по честной цене покупателям из пустошей,
если игроки давно в нём ничего не покупали.

Аренды хранятся в `Saves/<Мир>/<Игра>/ServerMultipass/VendingRental.json`. При первом запуске
модуль забирает аренды из `VendingRental.xml` отдельного мода VendingRental. Сам отдельный мод
нужно удалить: вместе с модулем он не работает.

Модуль меняет XML игры, поэтому включается и выключается после перезапуска сервера, см.
[Модули с XML игры](#модули-с-xml-игры). Выключенный модуль возвращает кнопку «Арендовать» и обычные
автоматы, а договор аренды и трейдер 51 остаются в игре: с ними сохранены поставленные игроками
автоматы и договоры в инвентарях.

| настройка | в поставке | что значит |
|---|---|---|
| `RentPrice` | `5000` | цена договора и каждого продления в дюках. Применяется после перезапуска сервера |
| `RentDays` | `30` | на сколько игровых дней продлевает одна оплата |
| `MaxRentalsPerPlayer` | `3` | сколько автоматов игрок арендует одновременно, вместе с забранными автоматами, аренда которых сохранена |
| `AutoBuyEnabled` | `true` | покупатели из пустошей покупают товары в арендованных автоматах |
| `AutoBuyRunsPerDay` | `4` | сколько раз за игровой день у автомата есть шанс такой продажи, от 0.01 до 96 |
| `AutoBuyChancePercent` | `30` | шанс продажи в каждый такой раз, в процентах |
| `AutoBuyIdleHours` | `12` | покупатели приходят, только если игроки не покупали в автомате столько игровых часов; новая аренда считается покупкой |
| `AutoBuyMaxMarkupPercent` | `30` | покупатели берут только товары с наценкой не выше стольких процентов |
| `AutoBuyExcludeItems` | пусто | имена предметов через запятую, которые покупатели не берут |

## Поведение при сбоях

* Модули не зависят друг от друга. Если модуль сбоит 10 раз за минуту, он сам выключается, пишет
  причину в лог и подсказывает, как включить его обратно. Остальные продолжают работать.
* Модуль, меняющий XML игры, после ошибок не выключается, а только пишет их в лог: XML игры на ходу
  не вернуть, и такой модуль без кода оставил бы игру в сломанном состоянии.
* Модуль, у которого файл настроек или текстов отсутствует или неверен, не включается, а в логе
  будут имя файла и суть проблемы. Остальные модули запускаются как обычно.
* Ошибка в файле, исправленном на работающем сервере, ничего не останавливает: в логе будут имя
  файла и суть проблемы, а в работе останутся прежние значения.
* Выключенный модуль никак не вмешивается в игру.
* Если файл с данными мира не читается, он сохраняется рядом копией `.broken`, а модуль начинает с
  пустыми данными, вместо того чтобы молча их потерять.

| [ProfLog](https://github.com/kotfoxtrot/7d2d_ProfLog) | профайлер выделенного сервера, только чтение |
